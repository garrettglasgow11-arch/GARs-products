# VOID ARENA

A round-based elimination arena for Roblox. Players drop onto a floating tiled
platform, the floor collapses ring by ring, and the last one standing wins.

Built by **GAR Productions**.

---

## What the game actually is

- **Lobby → 20s intermission → round → winner screen → repeat.** Forever, automatically.
- The arena is a disc of tiles. Starting 14 seconds in, the **outermost ring dissolves
  every 15 seconds**, and random single tiles crumble throughout. The floor is the timer.
- Two abilities, both **aim-free** so they work on a phone:
  - **PULSE** — a radial shockwave that damages and *shoves* everyone near you. This is
    how you win: knock people off the edge, don't grind their health down.
  - **DASH** — a burst of movement to save yourself when a tile drops out from under you.
- **Powerups** spawn on live tiles mid-round: MEND (heal), SURGE (speed + jump),
  OVERCHARGE (bigger, harder pulse).
- **Wins and Coins** persist between sessions via DataStore.
- Dead players get a **spectator camera** with tap-to-switch.

## Setup in Studio Lite (mobile) — 3 scripts, ~4 minutes

Everything else — the lobby, the arena, the lighting, the whole HUD, every
RemoteEvent — is generated by code when the game starts. **You never have to place
a Part or build a GUI by hand.** That is on purpose, because doing that on a phone
is miserable.

Open a **Baseplate** template, then:

### 1. `GameConfig`
- In the Explorer, tap **ReplicatedStorage** → **+** → **ModuleScript**
- Rename it exactly `GameConfig`
- Delete everything inside it, paste in **`src/1_GameConfig.lua`**

### 2. `ArenaServer`
- Tap **ServerScriptService** → **+** → **Script** (a plain Script, *not* a LocalScript)
- Rename it exactly `ArenaServer`
- Delete everything inside it, paste in **`src/2_ArenaServer.lua`**

### 3. `ArenaClient`
- Open **StarterPlayer** → tap **StarterPlayerScripts** → **+** → **LocalScript**
- Rename it exactly `ArenaClient`
- Delete everything inside it, paste in **`src/3_ArenaClient.lua`**

### 4. Play
Hit Play. The default Baseplate and SpawnLocation get removed automatically and the
world builds itself. You'll spawn in the lobby, and because `MinPlayers` is `1`, a
round starts on its own so you can test solo.

> If nothing happens, open the **Output** window. The server prints
> `[VoidArena] Server ready` and the client prints `[VoidArena] Client HUD ready.`
> If you only see one of them, that script is in the wrong place or misnamed.

## Before you publish

Open `GameConfig` and change:

```lua
Config.MinPlayers = 2    -- was 1 for solo testing
```

Optional but recommended: in Studio, **Game Settings → Security → Enable Studio Access
to API Services**. Without it, DataStore calls fail in Studio and your Wins/Coins reset
every test run. The game handles that failure quietly and keeps working — you just
won't keep progress while testing. Published games save fine either way.

## Tuning it

Every number is in `GameConfig`. Nothing else needs editing. The knobs that change
the game the most:

| Setting | Does what | Try |
|---|---|---|
| `RingInterval` | Seconds between ring collapses | Lower = faster, more brutal rounds |
| `CollapseDelay` | Calm time before the void starts | Lower for short-attention-span pacing |
| `Pulse.Force` / `Pulse.Lift` | How hard you shove people | `Lift` is what actually launches them off |
| `Pulse.Cooldown` | Pulse spam rate | 2.0 is chaotic, 5.0 is tactical |
| `Rings` | Arena size | 5 = cramped brawl, 9 = big map |
| `PowerupInterval` | Powerup frequency | Lower = more swingy |

### Sound
`Config.Sounds` is intentionally left blank — I didn't want to hardcode asset IDs
that might be dead or wrong on your account. To add audio, find sounds in the Toolbox,
copy their asset IDs, and fill them in:

```lua
Config.Sounds = {
    Pulse = "rbxassetid://YOUR_ID_HERE",
    ...
}
```

Then hook them up wherever you want them fired — the effect points are already
separated out in `ArenaClient` (`RE_Effect.OnClientEvent`).

## How it's put together

```
ReplicatedStorage
  GameConfig ............ every tunable number
  ArenaRemotes/ ......... created at runtime by the server
    State ............... server -> client HUD snapshot (once/sec + on events)
    Feed ................ server -> client kill feed line
    Effect .............. server -> client one-off VFX
    Ability ............. client -> server ability request

ServerScriptService
  ArenaServer ........... world building, round state machine, combat,
                          powerups, elimination credit, DataStore

StarterPlayerScripts
  ArenaClient ........... HUD, touch/keyboard/gamepad input, VFX,
                          camera shake, spectator camera
```

**The server is authoritative.** The client predicts its own ability cooldowns so the
buttons feel instant, but the server independently rejects any ability request that
comes in early, from a dead player, or outside a live round. Knockback and damage are
applied server-side only.

**Elimination credit** works on a 6-second window (`Config.CreditWindow`): if someone
pulsed you and you fall into the void within 6 seconds, they get the kill and the
coins. That's what makes ring-outs feel like kills instead of accidents.

**Knockback note:** shoving a grounded Humanoid barely works, because the humanoid
controller fights the impulse. `applyKnockback` puts the target into `Freefall` for a
moment first so physics wins. That's the line to look at if knockback ever feels weak.

## Known limits

- No matchmaking or teams — it's a single-server free-for-all.
- The arena rebuilds itself every round (~170 parts). Fine for normal server sizes;
  if you push `Rings` well past 9 you'll want to pool the tiles instead.
- Rounds that hit the full `RoundTime` are decided by most eliminations, health
  breaking the tie. In practice the collapsing floor ends rounds long before that.
